Apa itu Backend?

Backend adalah bagian "di balik layar" website yang bertugas menyimpan data, memproses logika bisnis, menjaga keamanan otentikasi, dan melayani data ke frontend melalui API.

🔗

Apa itu REST API?

REST API (Representational State Transfer) adalah standar komunikasi antara client dan server menggunakan protokol HTTP standar (GET, POST, PUT, DELETE) dengan data berformat JSON.

⚙️

Peran Node.js & Express

Node.js memungkinkan JavaScript berjalan di server, sedangkan Express.js adalah framework minimalis & cepat untuk membuat routing API dan middleware dengan mudah.

Standar HTTP

HTTP Status Code Explorer

Status code memberitahu klien apa yang terjadi pada request mereka. Klik kartu di bawah untuk mengirim request nyata ke server dan melihat responnya:

2xx: Sukses (Success) 3xx: Pengalihan (Redirection) 4xx: Kesalahan Klien (Client Error) 5xx: Kesalahan Server (Server Error)
200 OK

Request Berhasil

Standar untuk GET data yang sukses atau respon PUT yang mengembalikan data.

201 Created

Data Berhasil Dibuat

Digunakan saat operasi POST berhasil menambahkan data baru ke database.

204 No Content

Sukses Tanpa Body

Request berhasil, namun server sengaja tidak mengirim payload JSON (misal sehabis DELETE).

400 Bad Request

Format Data Tidak Valid

Input client salah, format JSON rusak, atau ada field wajib yang kosong.

401 Unauthorized

Belum Login / Tanpa Token

Client belum login atau tidak menyertakan Token otentikasi di Header.

403 Forbidden

Tidak Memiliki Hak Akses

Client sudah login, namun rolenya tidak diizinkan mengakses resource tersebut.

404 Not Found

Data / URL Tidak Ditemukan

Endpoint URL tidak terdaftar di router atau ID item tidak ada di database.

422 Unprocessable

Gagal Validasi Bisnis

Format syntax JSON benar, tetapi nilai tidak lolos aturan bisnis (misal email duplikat).

429 Too Many Req

Terlalu Banyak Request

Client memborbardir request melebihi batas rate limit per detik/menit.

500 Server Error

Bug Internal Server

Terjadi error runtime yang tidak tertangani (unhandled exception) pada backend.

Cheat Sheet & Referensi

Panduan & Contoh Kode Backend Lengkap

Pelajari pola sintaks Express.js yang sering digunakan di industri pengembangan backend nyata:

Inisialisasi Server Express Dasar

Struktur paling ringkas untuk membuat web server dengan Express.js:

// 1. Import library Express
const express = require('express');
const app = express();
const PORT = 3000;

// 2. Middleware agar server bisa membaca JSON di request body
app.use(express.json());

// 3. Routing sederhana
app.get('/', (req, res) => {
  res.json({ message: 'Halo dari Backend Express!' });
});

// 4. Jalankan server pada port yang ditentukan
app.listen(PORT, () => {
  console.log(`Server aktif di http://localhost:${PORT}`);
});

Pola Standar RESTful Routing (CRUD)

Penggunaan method HTTP yang tepat untuk setiap aksi data:

// [GET] Mengambil semua data
app.get('/api/users', (req, res) => {
  res.status(200).json({ data: users });
});

// [GET] Mengambil satu data berdasarkan ID (req.params)
app.get('/api/users/:id', (req, res) => {
  const userId = req.params.id;
  res.status(200).json({ data: user });
});

// [POST] Membuat data baru (req.body)
app.post('/api/users', (req, res) => {
  const { name, email } = req.body;
  res.status(201).json({ message: 'User berhasil dibuat' });
});

// [PUT] Memperbarui seluruh field data yang ada
app.put('/api/users/:id', (req, res) => {
  res.status(200).json({ message: 'User berhasil diupdate' });
});

// [DELETE] Menghapus data
app.delete('/api/users/:id', (req, res) => {
  res.status(200).json({ message: 'User berhasil dihapus' });
});

Membuat Custom Middleware

Middleware menerima 3 parameter: (req, res, next). Panggil next() untuk melanjutkan:

// Contoh 1: Logger Middleware (Mencatat Waktu & URL)
const loggerMiddleware = (req, res, next) => {
  console.log(`[${new Date().toISOString()}] ${req.method} ${req.url}`);
  next(); // Jangan lupa panggil next()!
};

// Pasang secara global ke semua request
app.use(loggerMiddleware);

// Contoh 2: Auth Middleware (Cek Token)
const requireAuth = (req, res, next) => {
  const authHeader = req.headers['authorization'];
  if (!authHeader) {
    return res.status(401).json({ error: 'Token wajib disertakan!' });
  }
  next();
};

// Pasang pada route tertentu saja
app.get('/api/rahasia', requireAuth, (req, res) => {
  res.json({ secret: 'Data rahasia perusahaan' });
});

Konsep Penyimpanan Data di Backend

Bagaimana backend berkomunikasi dengan database relasional (PostgreSQL/MySQL) atau NoSQL (MongoDB):

// Menggunakan Async / Await dengan database (Contoh Prisma / SQL)
app.get('/api/products', async (req, res) => {
  try {
    // 1. Query ke database secara asynchronous
    const products = await db.product.findMany({
      where: { inStock: true }
    });

    // 2. Kembalikan data hasil query
    res.status(200).json({ status: 'success', data: products });
  } catch (error) {
    // 3. Tangani jika database error
    res.status(500).json({ error: error.message });
  }
});

Global Error Handler di Express

Menangkap semua error yang terjadi di aplikasi agar server tidak crash tiba-tiba:

// 1. Handler jika endpoint URL tidak ditemukan (404)
app.use((req, res, next) => {
  res.status(404).json({
    status: 'error',
    message: 'Endpoint tidak ditemukan!'
  });
});

// 2. Global Error Handler (Wajib 4 parameter: err, req, res, next)
app.use((err, req, res, next) => {
  console.error('Terjadi Error:', err.stack);
  res.status(err.status || 500).json({
    status: 'error',
    message: err.message || 'Internal Server Error'
  });
});
